Permissions explained

Every permission and Android capability ClearGuard uses, in plain language: why it is needed, when it is used, what it never does, and how to turn it off.

App
ClearGuard for Android (com.veriattend.clearguard)
Updated
27 October 2026

ClearGuard requests only two Android permissions that you might see listed: notifications (optional) and request to delete packages (opens Android's own uninstall screen). Everything else below is a service you switch on yourself, or a system feature that needs no permission.

1. Accessibility service

You switch it on Core feature

Why
Android tells an app which other app brought a window to the front only through an Accessibility service. Without it ClearGuard cannot link a popup to an app.
When
Only during an observation session that you start, after you agree to the in app disclosure. Outside a session the service asks Android for no events at all. Sessions last 5 minutes to 2 hours and are interrupted when the screen turns off.
What it reads
For "window state changed" events only: the package name of the app, the event type and the time.
What it never does
Read window content or screen text (canRetrieveWindowContent="false"), perform gestures or taps (canPerformGestures="false"), take screenshots (canTakeScreenshot="false"), read what you type, or change settings or other apps.
Turn it off
Android Settings → Accessibility → ClearGuard (often under "Downloaded apps" or "Installed apps") → off. Or, in ClearGuard, withdraw consent on the Access screen: observation stops even while the Android setting is on.

ClearGuard is not an accessibility tool for people with disabilities, and declares this to Android (isAccessibilityTool="false"). Android's settings screen may describe broader abilities than ClearGuard uses; ClearGuard cannot change that wording.

The description Android shows on ClearGuard's Accessibility settings page:

During observation sessions you start in ClearGuard, this reads the package name, event type, and timing of app window changes. It does not read screen text or messages, take screenshots, or perform taps. Turning this on does not start observing; you start each session in ClearGuard.

2. The in app prominent disclosure

Before ClearGuard opens Android's Accessibility settings, it shows a separate sheet in the normal flow (when you first tap to start a session). It is not hidden in a menu, and it is not combined with any other notice. You must tap "Agree and open settings" to continue; "Not now", the back button or tapping outside count as no consent, and ClearGuard then observes nothing. If you decline, the sheet appears again the next time you try to start a session. The text, as shown in the app (disclosure version 3):

Before ClearGuard observes anything

ClearGuard uses Android Accessibility during observation sessions you start to read the package name, event type, and timing of selected app events, including while you use other apps. This helps you review possible sources of unexpected popups.

ClearGuard does not read screen text or messages, take screenshots, or perform taps.

Recent events stay temporarily in memory. When a session ends, a summary of which apps reported window changes is saved on this device automatically, unless nothing was observed. During a session, ClearGuard may save an "Awaiting review" incident automatically when an app's window appears unexpectedly. Saved incidents and sessions stay on this device until you delete them or retention expires. This data is not sent to or shared with us or anyone else.

Some popups do not reveal their source.

Android's own settings screen may describe broader abilities than ClearGuard uses. ClearGuard cannot change that wording.

[Agree and open settings] [Not now]

ClearGuard stores the disclosure version and the time you agreed. If the disclosure changes in a way that affects what is read, you are asked again before anything is observed.

3. How this follows Google Play's Accessibility API policy

  • Disclosed purpose only. The service is used for one function: showing which app reported a window change near a popup you mark, or that automatic detection saves for your review. It is not used for advertising, analytics, or anything else.
  • User initiated. You switch the service on in Android settings and you start every session. ClearGuard does not start sessions by itself; even the optional reminder only opens the app.
  • Prominent disclosure and affirmative consent in the app, before Android settings open, as shown above. The Android service description is extra and does not replace it.
  • Narrowest configuration. One event type (typeWindowStateChanged), no window content, no gestures, no screenshots.
  • No autonomous actions. ClearGuard never taps, changes settings, or stops you from disabling or uninstalling any app, including itself.
  • No circumvention of Android's security, privacy controls or notifications.
  • Not declared as an accessibility tool, so it meets the disclosure and consent requirements instead.
  • Documented in the Play store listing description and in the Play Console Accessibility declaration.

4. Floating bubble

No extra permission

Why
Lets you mark a popup with one tap without leaving the app you are in.
When
Only while a session runs (dimmed while paused), and never over ClearGuard itself. It is drawn by ClearGuard's Accessibility service, so it needs no "Display over other apps" permission and disappears with the service.
What it never does
Read anything from the screen. It shows only ClearGuard's own icon, or the icon of the app ClearGuard thinks may be behind a popup.
Turn it off
ClearGuard Settings → Floating bubble, or drag it onto the X to hide it for the current session.

5. Notifications POST_NOTIFICATIONS

Optional Runtime permission

Why
Shows ClearGuard's own session controls (Mark, Pause, Stop), a quiet note when a popup is saved, and the optional reminder.
When
Requested only when you tap "Allow notifications" on the Access screen or in the reminder settings. Everything works without it.
What it never does
Show package names in the session notification, or show ads. On the lock screen the saved popup note only says "Possible popup from an app".
Turn it off
ClearGuard Settings → ClearGuard notifications, or Android Settings → Apps → ClearGuard → Notifications.

6. Request delete packages REQUEST_DELETE_PACKAGES

Install time

Why
The "Uninstall" button in Recent apps (and in the device admin helper of the Permissions checkup) opens Android's own uninstall confirmation for an app you picked.
When
Only when you tap Uninstall on an app.
What it never does
Uninstall anything by itself. Android asks you to confirm, and you can cancel. System apps get no Uninstall button.
Turn it off
It is not a switchable permission. If you do not want it used, simply do not tap Uninstall; App info works as an alternative.

7. Package visibility (which apps ClearGuard can see)

No permission

Why
To show app names and icons in results, the Visible apps list and the Permissions checkup; to recognise the home screen and share sheet as context rather than popups; and to find your web browsers for the Guides.
Scope
A narrow declaration: apps with a launcher icon, home apps, the share sheet, and apps that open web links. ClearGuard does not use QUERY_ALL_PACKAGES.
What it never does
Send the list of your apps anywhere.

8. Quick Settings "Mark popup" tile

You add it

An optional tile you can drag into Quick Settings to mark a popup during a session. It can only be bound by Android's System UI. Remove it any time by editing your Quick Settings tiles.

9. Home screen widget

You add it

An optional widget that shows whether a session is running and lets you mark a popup. It never names an app, never wakes the phone on a schedule, and never starts a session without a choice inside the app. Remove it like any widget.

10. Session reminder

Off by default No extra permission

If you turn on "Remind me to check for popups" (daily or every 3 days), ClearGuard sets an ordinary, inexact Android alarm to show one notification. It never starts a session, is skipped while a session runs, and does not use exact alarms or start at boot. Turn it off in ClearGuard Settings.

11. Other technical entries

  • DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION: added automatically by the AndroidX library to keep ClearGuard's internal broadcasts private to ClearGuard. It grants no access to your data.
  • Screen off signal: ClearGuard listens for the screen turning off, with no permission, so it can interrupt a session.
  • Google Play In App Review: may ask Google Play once to show its rating prompt. It adds no permission.

12. What ClearGuard does not request

  • Internet access (INTERNET) or network state
  • Display over other apps (SYSTEM_ALERT_WINDOW)
  • Usage access (PACKAGE_USAGE_STATS) or all packages visibility (QUERY_ALL_PACKAGES)
  • Foreground service, start at boot, or exact alarms
  • Location, contacts, phone, SMS, camera, microphone, photos or files
  • Device admin, VPN, or notification listener
